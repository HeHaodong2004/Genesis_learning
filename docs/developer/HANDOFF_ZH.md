# 中文交接

## 回来后从哪里开始

只打开根目录 `START_HERE.md`，按第一天的三条命令开始。你不需要先读完整研究交接或理解所有目录。先完成配对评估starter，再按两周顺序进入物理、观测、GAE、辨识。

## 已经给你的东西

- 一个独立工作树 `genesis-developer-workbench`，分支 `codex/developer-workbench`。
- `doctor / config / inspect-run` 三个可用工具，帮助检查环境、配置与实验元数据。
- VS Code工作区建议、调试入口、Makefile、轻量CI和PR模板。
- 四套需要你实现核心的纯CPU练习，含starter、参考解与测试；一个已CPU/GPU实测的Genesis物理仪器。
- 中文两周跟练入口、12周/三年路线、工程手册、实验卡、每日复盘与交接模板。
- 可导出的独立GitHub教学快照，不携带原研究历史和大体积结果。

验证数字和范围见 [VALIDATION.md](VALIDATION.md)。你运行默认测试看到绿灯，代表参考实现通过；学习验收必须显式选择starter并解释一个新反例。

## 给未来的自己或另一个AI

先读 [背景摘要](learner-context.md)，再读你当前练习。主线是独立机器人学习研究能力，保留数学、最小模型、证伪与严谨观测边界；不要因为可用技术多就扩建大框架。

下一次指导可直接用：

> 我正在做 START_HERE 中第X项。请先让我解释预测，再看我的starter实现与测试失败。每次只给一个诊断提示，不直接贴参考解。最后让我设计一个原测试没覆盖的反例，并检查我的解释是否超过证据。

不使用AI也可以完成近期练习：先读契约、写手算结果、实现、跑测试、定位失败、最后对照参考。遇到框架接口问题沿教程末尾官方资料查证，不需要重装整个环境。

## 采用与回退

原 `genesis-research` 的科学代码不必立即合并本工作台。可以一直在独立目录学习；将来选一个小工具或修复，单独做评审。不要直接把教学统计契约替换进历史结果生成器，也不要把GAE练习通过当成完整训练器已修复。

本地未启动持续服务。物理探针已结束，未留下训练/GPU后台任务。未安装或升级现有Genesis环境依赖。GitHub上传使用独立教学快照，最终链接和远端验证状态由本次对话交付。
